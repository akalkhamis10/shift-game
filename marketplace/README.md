# مَرسم — سوق فنّ الذكاء الاصطناعي

منصة Marketplace تربط **الشركات** بـ **صنّاع المحتوى بالذكاء الاصطناعي** على نموذج 99designs:
الشركة تطلق مسابقة بموجز وجائزة، المبدعون يقدّمون أعمالهم، والشركة تختار الفائز وتستلم الملكية.

## أنواع الأعمال (17 تصنيفًا في 3 مجموعات)

| المجموعة | التصنيفات | معامل السعر |
|---|---|---|
| 🖼️ **صور وتصميم** | شعار وهوية، رسم توضيحي، تصوير منتجات، شخصيات وماسكوت، بوسترات وأغلفة، منشورات سوشال، فن مفاهيمي وألعاب | ×1 |
| 🎬 **فيديو وأفلام** | أفلام قصيرة (×2)، إعلانات فيديو (×1.6)، قصص وأنيميشن (×1.6)، فيديو تعليمي (×1.4)، موشن جرافيك (×1.3)، متحدث افتراضي (×1.2)، ريلز وتيك توك (×1) | ×1 – ×2 |
| 🎧 **صوت وموسيقى** | تعليق صوتي/فويس (×0.8)، موسيقى وجنغل (×1)، بودكاست وكتب صوتية (×0.8) | ×0.8 – ×1 |

- كل تصنيف يحدد **نوع الملف المقبول**؛ المنصة (والقاعدة) ترفض صورة في مسابقة فويس مثلًا.
- الموجز يضيف حقولًا حسب التصنيف: **المدة، المقاس (16:9 / 9:16…)، اللهجة، صوت المتحدث، المزاج الموسيقي، والنص/السكربت** (إلزامي للفويس والمتحدث الافتراضي).
- الإفصاح عن **كل** الأدوات المستخدمة (مثلًا Veo + ElevenLabs + Suno)، وسياسة صريحة لاستنساخ الأصوات: صوت الفنان نفسه أو بموافقة مكتوبة فقط.
- الفيديو يُعرض بمشغّل مع صورة غلاف مستخرجة تلقائيًا، والصوت بمشغّل وموجة صوتية (waveform) محسوبة من الملف.
وبجانب المسابقات: **مشاريع مباشرة** (1-to-1) مع فنان بعينه.

> النسخة الحالية **نموذج أولي يعمل بالكامل في المتصفح** (بدون سيرفر)؛ البيانات في `localStorage`، وملفات الفيديو والصوت
> المرفوعة في IndexedDB (في نفس المتصفح فقط)، والدفع وهمي. عيّنات العرض مولّدة محليًا: الفيديو معاينة متحركة،
> والموسيقى ملف WAV حقيقي يُولَّد من بذرة، والفويس يُقرأ بصوت المتصفح.
> ملف `supabase/schema.sql` هو تصميم قاعدة البيانات للإنتاج.

## التشغيل

بدون أي build — أي سيرفر ملفات ثابتة:

```bash
cd marketplace && python3 -m http.server 8080
```

ثم افتح http://localhost:8080. وبعد الدمج في `main` تكون على GitHub Pages:
`https://akalkhamis10.github.io/shift-game/marketplace/`

شريط «وضع العرض» أعلى الصفحة يسمح بالتبديل بين الحسابات (شركة / فنان / إدارة) وإعادة ضبط البيانات.

## المزايا

**للشركات**
- معالج إطلاق مسابقة من 4 خطوات: التصنيف ← الموجز ← الباقة والخيارات ← الدفع.
- 4 باقات (برونزي 1,100 / فضي 1,900 / ذهبي 3,000 / بلاتيني 5,600 ر.س) — المبلغ يبقى في **الضمان**.
- خيارات: جائزة مضمونة، مسابقة **سرية** (الفنانون لا يرون أعمال بعض)، ظهور مميّز.
- تقييم كل تصميم بالنجوم، قائمة نهائية (حتى 6)، استبعاد، ملاحظات خاصة مع كل فنان.
- اختيار الفائز ← تحرير الجائزة للفنان + **ملف تسليم** (الصورة + البرومبت + شهادة نقل الملكية).
- تمديد المسابقة، إغلاق المشاركات مبكرًا، أو **استرداد كامل** إن لم تكن مضمونة.
- توظيف فنان مباشرة: طلب ← قبول ← تسليم ← (تعديل) ← اعتماد وتحويل المبلغ.

**للفنانين**
- تصفّح وفلترة المسابقات حسب النوع (صور / فيديو / صوت) والتصنيف.
- رفع صورة (تُصغَّر تلقائيًا) أو فيديو حتى 80MB أو صوت حتى 25MB — سحب وإفلات، حتى 5 مشاركات نشطة لكل مسابقة.
- **إفصاح إلزامي عن أدوات الذكاء الاصطناعي** + إقرار بالأصالة وحقوق النقل وموافقة أصحاب الأصوات/الوجوه.
- البرومبت خاص ولا يظهر للعميل إلا عند الفوز.
- ملف عام (معرض أعمال، فوز، تقييمات)، محفظة وسحب إلى آيبان سعودي، إشعارات.

**للإدارة**
- إحصاءات المنصة (GMV، الإيراد، المدفوع للفنانين، المستردّات)، جداول المسابقات والمستخدمين، إزالة المشاركات المخالفة.

**نموذج الربح:** الفرق بين سعر الباقة والجائزة في المسابقات + 10% من المشاريع المباشرة (+ إضافات السرية/التمييز).

## البنية

```
marketplace/
├── index.html          الهيكل (RTL، خط IBM Plex Sans Arabic)
├── styles.css          التصميم والاستجابة للجوال
├── js/app.js           الراوتر (hash) + معالجات الأحداث
├── js/views.js         كل الصفحات والنوافذ
├── js/store.js         منطق الأعمال وقواعد الصلاحيات + بيانات العرض
├── js/media.js         الفيديو والصوت: تخزين IndexedDB، غلاف الفيديو، الموجة الصوتية، عيّنات العرض
├── js/art.js           مولّد صور إجرائي (SVG) لبيانات العرض — بلا صور خارجية
├── js/ui.js            قوالب HTML آمنة (escape تلقائي)، تنسيق، Toast، Modal
└── supabase/schema.sql قاعدة بيانات الإنتاج + RLS + دوال الدفع
```

كل تعديل على البيانات يمر عبر دوال `store.js` (مثل `pickWinner` و`submitEntry`)، لذلك الانتقال للإنتاج يعني
استبدال جسم هذه الدوال باستدعاءات Supabase دون لمس الواجهات.

## الطريق إلى الإنتاج

1. **قاعدة البيانات:** تطبيق `supabase/schema.sql` على مشروع Supabase مستقل (لا تخلطه مع مشروع اللعبة).
2. **الدخول:** Supabase Auth برابط سحري (نفس أسلوب `admin.html` في اللعبة) + إنشاء صف في `profiles`.
3. **الملفات:** Supabase Storage (bucket خاص `entries`) مع روابط موقّعة تحترم قاعدة المسابقات السرية.
   الفيديو الكبير يحتاج رفعًا مجزّأً (TUS) وتحويلًا لصيغ البث (HLS) وعلامة مائية على المعاينات قبل الفوز —
   خدمة مثل Mux أو Cloudflare Stream أنسب من تخزين الملفات الخام.
4. **الدفع والضمان:** بوابة محلية (Moyasar / Tap / HyperPay) تدعم مدى وApple Pay؛
   الـ webhook يستدعي `launch_contest`، والتحويل للفنانين عبر تحويل بنكي/Payouts API.
   كل حركة مالية داخل دوال `security definer` فقط — المتصفح لا يكتب في `transactions`.
5. **الامتثال:** فواتير ضريبية إلكترونية (ZATCA)، تحقق هوية الفنانين قبل السحب، شروط استخدام وسياسة خصوصية (PDPL).
6. **مهام مجدولة:** إشعار قبل انتهاء المسابقة، وتذكير العميل باختيار الفائز خلال 7 أيام من التحكيم.
7. **الإشراف:** فحص تشابه الصور (perceptual hash) لكشف النسخ، وبلاغات من المستخدمين.
